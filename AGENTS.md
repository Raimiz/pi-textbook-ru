# AGENTS.md

Этот файл определяет правила работы агентов над русской редакцией Pi Textbook.

Он обязателен для любого агента, который переводит, редактирует, рецензирует, проверяет терминологию, анализирует код или участвует в обсуждении спорных формулировок.

## Цель проекта

Создать русскую редакцию Pi Textbook, которая:

- точно передаёт смысл оригинала;
- читается как изначально написанный по-русски технический текст;
- сохраняет авторский ритм, структуру и инженерную логику;
- использует последовательную терминологию;
- не превращается в буквальный машинный перевод;
- остаётся верной оригиналу и явно отделяет редакторские дополнения от авторского текста.

Проект рассматривается не только как перевод, но и как внимательное техническое чтение книги.

## Роль основного агента

Основной агент совмещает четыре роли:

1. **Технический переводчик** — понимает исходный текст, код и архитектурный контекст.
2. **Редактор** — делает русский текст естественным, ясным и профессиональным.
3. **Технический рецензент** — проверяет точность утверждений, терминов и причинно-следственных связей.
4. **Хранитель редакционной последовательности** — следит за глоссарием, принятыми решениями и стилем всей книги.

Основной агент не должен защищать собственную формулировку. Его задача — найти лучший вариант.

## Роль дополнительных агентов

Дополнительный агент может подключаться как:

- независимый рецензент;
- технический эксперт;
- редактор русского текста;
- критик терминологии;
- проверяющий соответствие оригиналу;
- специалист по коду Pi;
- участник разбора спорной формулировки.

Дополнительный агент обязан сначала изучить:

- этот файл;
- `TRANSLATION.md`;
- `GLOSSARY.md`;
- относящиеся к вопросу редакционные решения;
- оригинальный фрагмент;
- текущий русский вариант.

Он не должен предлагать замену, не объяснив, какую конкретно проблему она решает.

## Порядок работы над главой

Каждая глава проходит три обязательных этапа:

1. **Технический перевод**
   - установить точный смысл;
   - проверить термины и связи с кодом;
   - не улучшать автора за счёт изменения смысла.

2. **Редакторская переработка**
   - убрать кальки;
   - перестроить фразы, если русский синтаксис требует этого;
   - сохранить краткость и ритм оригинала;
   - сделать текст естественным для русскоязычного разработчика.

3. **Техническая и терминологическая проверка**
   - сверить русский вариант с оригиналом;
   - проверить код, команды, названия интерфейсов и концепции;
   - проверить единообразие терминов по всей книге.

Глава не считается завершённой, пока не пройдены все три этапа.

## Работа со спорными формулировками

Если формулировка вызывает сомнение, агент должен:

1. привести исходный фрагмент;
2. описать смысл, который необходимо сохранить;
3. указать проблему текущего варианта;
4. предложить один основной вариант и при необходимости один-два альтернативных;
5. объяснить различия между вариантами;
6. не менять утверждённую терминологию без явного обсуждения.

В споре не используется голосование. Выбирается вариант, который одновременно:

- точнее передаёт смысл;
- естественнее звучит по-русски;
- лучше соответствует контексту главы;
- сохраняет терминологическую последовательность.

Окончательное редакционное решение принимает владелец русской редакции.

## Принципы перевода

- Переводить смысл, а не структуру предложения.
- Допускается полностью переписать фразу, если смысл и функция сохраняются.
- Не добавлять объяснения внутрь авторского текста без необходимости.
- Не использовать канцелярит и псевдоакадемический стиль.
- Не усложнять простой текст.
- Не заменять точный инженерный термин расплывчатым бытовым словом.
- Не оставлять английский термин только потому, что его трудно перевести.
- Не переводить термин только ради формального устранения английского слова.
- Названия сущностей, интерфейсов, API и элементы кода сохранять в исходном виде, если иное не закреплено в глоссарии.

## Терминология

Утверждённые термины имеют приоритет над личными предпочтениями агента.

Не переводятся:

- Pi
- Tool Calling
- Agent Loop
- runtime
- checkpoint
- prompt
- TypeScript
- JSON
- API
- CLI
- SDK
- HTTP
- SSE
- WebSocket

Утверждённые переводы:

- Session Tree — дерево сессий
- Streaming — потоковая обработка
- Context Compression — сжатие контекста
- Trace — трассировка
- Chapter — глава
- Lesson — урок
- Layer — слой
- Program — Курс
- Method — Методика
- Glossary — Глоссарий

При конфликте между этим списком и `GLOSSARY.md` приоритет имеет более новое явно зафиксированное редакционное решение.

## Примечания переводчика

Примечание добавляется только тогда, когда без него русскоязычный читатель с высокой вероятностью неверно поймёт текст или потеряет важный контекст.

Правило:

> Если текст можно понять без примечания, примечание не нужно.

Любое примечание должно быть явно отделено от авторского текста и не должно выдавать редакторское мнение за позицию автора.

## Наблюдения и технический анализ

Во время работы агенты фиксируют отдельные наблюдения о:

- педагогической структуре курса;
- архитектуре Pi;
- эволюции решений от главы к главе;
- сильных и спорных местах книги;
- связях с другими агентными системами;
- идеях для будущего предисловия.

Эти наблюдения не должны незаметно попадать в перевод. Они записываются отдельно в `OBSERVATIONS.md`.

## Изменения в исходном коде

При работе с кодом и интерфейсом агент обязан:

- не менять поведение приложения без отдельной причины;
- не смешивать локализацию с архитектурным рефакторингом;
- сохранять компилируемость проекта;
- запускать доступные проверки после изменений;
- не переводить идентификаторы, пути, имена компонентов и API без технической необходимости;
- проверять, что локализованный текст не ломает вёрстку.

## Коммиты

Коммиты должны быть небольшими и тематически цельными.

Предпочтительные префиксы:

- `docs:` — редакционные документы, глоссарий, наблюдения;
- `i18n:` — перевод и локализация интерфейса или глав;
- `fix:` — исправления ошибок перевода, разметки или поведения;
- `refactor:` — только для отдельно согласованного технического рефакторинга.

Не следует объединять перевод нескольких несвязанных глав и изменения инфраструктуры в один коммит.

## Запрещённые действия

Агент не должен:

- массово переводить главы без последующей редакторской проверки;
- менять утверждённые термины молча;
- придумывать отсутствующий в оригинале смысл;
- сглаживать технические противоречия автора без фиксации;
- выдавать собственное объяснение за перевод;
- удалять авторские оговорки, ограничения и нюансы;
- использовать `main` как рабочую ветку;
- сливать изменения в `main` до завершения полной редакционной проверки.

## Рабочая ветка и выпуск

Текущая рабочая ветка:

- `agent/russian-site-landing`

Стабильная русская редакция:

- `main`

Оригинал:

- `upstream-zh`

Слияние в `main` выполняется только после завершения перевода, общего редакторского прохода и проверки терминологической последовательности.

## Главный критерий качества

Русский читатель не должен чувствовать, что перед ним машинный или буквальный перевод.

При этом специалист, сравнивший текст с оригиналом, должен увидеть, что смысл, структура аргумента и авторская позиция сохранены.
