# Checklist проверки главы

Глава считается готовой только после прохождения всех применимых пунктов.

## 1. Смысл

- [ ] Все утверждения оригинала сохранены.
- [ ] Оговорки, ограничения и степень уверенности автора не потеряны.
- [ ] Причинно-следственные связи не упрощены.
- [ ] Не добавлены новые технические утверждения.
- [ ] Не исправлены молча возможные ошибки оригинала.
- [ ] Роль главы в общей эволюции проекта понятна.

## 2. Русский текст

- [ ] Текст читается естественно без обращения к оригиналу.
- [ ] Нет буквальных синтаксических калек.
- [ ] Нет канцелярита и псевдоакадемических конструкций.
- [ ] Понятно, кто выполняет каждое действие.
- [ ] Предложения не перегружены лишними связками.
- [ ] Заголовки короткие и грамматически согласованные.
- [ ] Списки имеют единый грамматический рисунок.
- [ ] Ритм и степень подробности соответствуют оригиналу.

## 3. Терминология

- [ ] Все утверждённые термины соответствуют `GLOSSARY.md`.
- [ ] Название механизма не смешано с названием отдельного действия.
- [ ] Один концепт не получил несколько случайных переводов.
- [ ] Английские термины оставлены только по осознанной причине.
- [ ] Новые термины добавлены в глоссарий или отмечены для обсуждения.
- [ ] Спорные решения внесены в `DECISIONS.md`.

## 4. Код и технические детали

- [ ] Идентификаторы, пути, команды и ключи JSON сохранены корректно.
- [ ] Кодовые блоки совпадают с логикой объяснения.
- [ ] Перевод комментариев и строк не меняет поведение примера.
- [ ] Ожидаемый вывод, тестовые данные и снапшоты не повреждены.
- [ ] Названия API, типов, методов и событий проверены.
- [ ] Ссылки на предыдущие реализации и checkpoint корректны.
- [ ] Технические утверждения проверены по коду или документации, если возникло сомнение.

## 5. Интерфейс и разметка

- [ ] Русские строки помещаются в компоненты.
- [ ] Кнопки и подписи согласованы с остальным интерфейсом.
- [ ] Markdown, MDX или JSX-разметка не повреждена.
- [ ] Ссылки, якоря и навигация работают.
- [ ] Таблицы и списки отображаются корректно.
- [ ] Изображения, подписи и альтернативный текст проверены.

## 6. Примечания и наблюдения

- [ ] Каждое примечание переводчика действительно необходимо.
- [ ] Примечания явно отделены от авторского текста.
- [ ] Редакторское мнение не выдано за позицию автора.
- [ ] Инженерные наблюдения записаны в `OBSERVATIONS.md`, а не внедрены в перевод.
- [ ] Предварительные гипотезы помечены как предварительные.

## 7. Проверка изменений

- [ ] Просмотрен diff относительно исходной версии.
- [ ] В коммит не попали несвязанные изменения.
- [ ] Запущены доступные тесты, линтер и сборка.
- [ ] Результаты проверок зафиксированы в описании работы или PR.
- [ ] Проверена вёрстка в браузере, если глава содержит UI.

## 8. Независимое чтение

- [ ] Фрагмент прочитан как русская техническая глава без взгляда на оригинал.
- [ ] Затем фрагмент повторно сверен с оригиналом.
- [ ] Все места, где редактор остановился или перечитал фразу, пересмотрены.
- [ ] Спорные места вынесены на обсуждение с конкретным описанием проблемы.

## 9. Завершение

- [ ] Обновлён `ROADMAP.md`.
- [ ] При необходимости обновлён `CHANGELOG.md`.
- [ ] Глава получила редакционное одобрение владельца русской версии.

## Результат проверки

При завершении главы можно добавить краткую запись:

```markdown
Глава: ...
Технический перевод: выполнен
Редакторский проход: выполнен
Техническая проверка: выполнена
Сборка/тесты: ...
Новые термины: ...
Редакционные решения: ...
Открытые вопросы: ...
```
