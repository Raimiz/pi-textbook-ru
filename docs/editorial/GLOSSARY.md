# Глоссарий Pi Textbook

Глоссарий фиксирует утверждённые термины русской редакции и кратко объясняет их смысл в контексте курса.

Это живой документ. Новые термины добавляются по мере перевода глав. Изменение уже утверждённой формы требует записи в [`DECISIONS.md`](./DECISIONS.md).

## Статусы

- **Утверждено** — использовать во всём проекте.
- **Рабочий вариант** — допустимо в текущем черновике, но решение ещё может измениться.
- **На обсуждении** — не распространять на другие главы до решения.

## Основные термины

### Agent Loop

**Форма:** Agent Loop  
**Статус:** утверждено  
**Не переводить как:** агентный цикл без отдельного решения

Основной цикл работы агента: модель получает текущее состояние, формирует ответ или Tool Calling, runtime выполняет действие, обновляет состояние и запускает следующую итерацию.

### API

**Форма:** API  
**Статус:** утверждено

Программный интерфейс, через который компоненты взаимодействуют друг с другом. В коде и тексте сохраняется аббревиатура API.

### checkpoint

**Форма:** checkpoint  
**Статус:** утверждено  
**Не переводить как:** контрольная точка, снимок — без учёта контекста

Зафиксированное состояние проекта или этап курса, к которому можно вернуться. В книге checkpoint одновременно служит учебной вехой и воспроизводимой версией реализации.

### CLI

**Форма:** CLI  
**Статус:** утверждено

Интерфейс командной строки.

### Context Compression

**Форма:** сжатие контекста  
**Статус:** утверждено

Механизм уменьшения объёма истории, передаваемой модели, с сохранением информации, необходимой для продолжения работы агента.

### context window

**Форма:** контекстное окно  
**Статус:** рабочий вариант

Максимальный объём токенов, который модель может учитывать в одном запросе. Не смешивать с текущим содержимым контекста.

### HTTP

**Форма:** HTTP  
**Статус:** утверждено

Протокол передачи данных, используемый для запросов между клиентом и сервером.

### JSON

**Форма:** JSON  
**Статус:** утверждено

Текстовый формат структурированных данных.

### Layer

**Форма:** слой  
**Статус:** утверждено

Отдельный уровень системы с определённой ответственностью. Формулировка ошибки должна позволять понять, на каком слое она возникла.

### offline model

**Форма:** локальная офлайн-модель  
**Статус:** рабочий вариант

Модель, которая запускается без обращения к внешнему облачному API. Конкретная форма зависит от предложения: «офлайн-модель», «локальная модель» или «модель, работающая полностью локально».

### Pi

**Форма:** Pi  
**Статус:** утверждено

Проект и референсная реализация агента, на основе которой курс последовательно раскрывает устройство LLM-агентов.

### prompt

**Форма:** prompt  
**Статус:** утверждено

Инструкция или набор сообщений, передаваемых модели. Не переводить автоматически как «запрос»: запрос может включать и другие данные, а prompt может состоять из нескольких сообщений и системных инструкций.

### runtime

**Форма:** runtime  
**Статус:** утверждено  
**Не переводить как:** среда выполнения — автоматически

Компонент, управляющий выполнением агента: состоянием, обращением к модели, Tool Calling, событиями, итерациями и связанными механизмами жизненного цикла.

### SDK

**Форма:** SDK  
**Статус:** утверждено

Набор библиотек и инструментов для разработки.

### Session Tree

**Форма:** дерево сессий  
**Статус:** утверждено  
**Не переводить как:** дерево диалогов

Ветвящаяся структура состояний сессии, позволяющая сохранять альтернативные продолжения, возвращаться к предыдущим узлам и не сводить историю к одной линейной цепочке сообщений.

### SSE

**Форма:** SSE  
**Статус:** утверждено

Server-Sent Events — механизм однонаправленной потоковой передачи событий от сервера клиенту по HTTP.

### Streaming

**Форма:** потоковая обработка  
**Статус:** утверждено

Постепенная передача и обработка результата по мере его появления, а не ожидание полного ответа. В конкретной фразе допустимы формы «потоковый ответ», «потоковая передача» или «получать ответ по частям», если они точнее описывают действие.

### Tool Calling

**Форма:** Tool Calling  
**Статус:** утверждено  
**Не переводить как:** вызов функций — без учёта механизма

Механизм, при котором модель формирует структурированный запрос на выполнение внешнего инструмента, а runtime выполняет инструмент и возвращает результат в контекст агента.

Действие в обычном предложении можно выразить по-русски: «вызвать инструмент», «модель запросила вызов инструмента». Название механизма остаётся Tool Calling.

### tool

**Форма:** инструмент  
**Статус:** утверждено

Внешняя функция или операция, доступная агенту через Tool Calling: команда, API, поиск, чтение файла и другое действие.

### tool call

**Форма:** вызов инструмента  
**Статус:** утверждено

Один конкретный структурированный запрос модели к инструменту. Отличать от Tool Calling как общего механизма.

### Trace

**Форма:** трассировка  
**Статус:** утверждено

Последовательная запись событий выполнения, позволяющая восстановить ход работы агента и найти слой, на котором возникла проблема.

### TypeScript

**Форма:** TypeScript  
**Статус:** утверждено

Язык программирования, используемый в проекте.

### WebSocket

**Форма:** WebSocket  
**Статус:** утверждено

Двунаправленный канал связи между клиентом и сервером поверх одного длительного соединения.

### working memory

**Форма:** рабочая память  
**Статус:** рабочий вариант

Текущее состояние и информация, непосредственно используемые агентом при выполнении задачи. Точное определение будет уточняться по контексту соответствующей главы.

## Как добавлять термин

Для нового термина указать:

1. исходную форму;
2. утверждаемую русскую форму;
3. статус;
4. краткое определение в контексте Pi;
5. нежелательные или ошибочные варианты, если риск путаницы существенен;
6. ссылку на решение, если термин был спорным.
