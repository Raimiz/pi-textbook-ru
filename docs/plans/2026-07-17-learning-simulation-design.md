# 教材学习模拟设计

## 目标

验证一名没有 Agent 工程、TypeScript 流式协议和工具循环经验的学习者，能否只依赖教材与遵守提示阶梯的陪练，从第 00 章走到第 14 章。测试对象不是“学生最终能否抄出答案”，而是教材是否能让学生形成正确预测、找到第一步、解释测试失败，并在有限提示后独立完成本章 checkpoint。

## 选择的实验结构

采用“逐章隔离、认知连续”的黑盒重建。学生与陪练是两个不继承主线程上下文的 subagent。学生按课程顺序累积概念，但每章都在从该章 parent commit 导出的独立目录中工作；该目录不含目标 Git 历史，因此学生无法查看答案。陪练可以检查目标 commit 和聚焦测试，但不能直接给完整实现，只能按“定位文件 → 指出签名 → 伪代码 → 局部代码”逐级提示。主 agent 在两者之间转发学生的原始行为、错误输出与陪练的单步提示，并负责判断失败属于教材、陪练还是实现。

相比只读审稿，这种方式能观察真实的检索、预测和调试行为；相比一条累积代码分支，它不会让早期偶然偏差污染后续章节，也能从同一个 parent 精确复测。代价是它不能完全复制人类的疲劳和时间压力，因此“通过”只证明教材具备可执行的认知路径，不证明所有读者都能以相同速度掌握。

## 通过标准

每章至少收集：首次复述、首次动作、首次失败、提示级别、最终测试、学生置信度、陪练判责。若学生无法指出第一处修改、教材与测试签名冲突、关键前置概念首次出现却无解释、或必须看到局部代码才能继续，则本章失败。修复必须先形成一个可检查的内容契约或回归案例，再修改教材；随后从同一 parent 建立新目录，重复同一任务。只有原失败不再出现、聚焦测试通过、学生能用自己的话解释不变量，才算修复。

## 产物

- `docs/usability/learning-simulation.md`：逐章行为轨迹与判责；
- `docs/usability/regressions.json`：每个缺陷、修复和复测证据；
- `scripts/validate-learning-contract.mjs`：可自动检查的教材可学性契约；
- 修订后的章节、作者契约和陪练提示；
- 全量内容、类型、实现、历史与渲染测试结果。
