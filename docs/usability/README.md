# 教材可用性测试协议

这里记录的不是“审稿意见”，而是一次可重复的学习实验。测试问题只有一个：
学习者能否把正文中的因果解释，转成目标 commit 中的第一个可执行动作。

## 两个角色

- **学生**：会基本编程，但没有 Agent 工程、TypeScript 流协议、工具循环、
  session tree 或 context compaction 经验。只读当前章、隔离 parent 快照与
  聚焦测试，不读 target diff、`workshop/` 或参考实现。
- **陪练**：可以看 parent、target、测试和教材，但不能写学生文件。每次只给
  一个动作，并严格按 L0 预测、L1 文件、L2 符号、L3 伪代码、L4 局部代码升级。

主 agent 负责原样路由学生的行为和错误、判断责任层、修改教材并组织复测。

## 每章固定轨迹

1. 学生只读本章，复述目标、不变量、第一动作、未知术语和 0–5 置信度。
2. 从本章 parent 导出无目标历史的隔离目录；00 是例外，直接观察 target。
3. 只注入聚焦测试，学生先预测再运行；任何错误都记录首次偏差。
4. 陪练一次只给一个提示，学生再次运行同一测试。
5. 学生测试通过后，还要用自己的话解释不变量；只会复述代码不算通过。
6. 陪练判断卡点属于教材缺口、必要挣扎、未按步骤或测试/夹具问题。
7. 教材缺口先进入 `regressions.json`，再修改正文或工具。
8. 每次修改后从相同 parent 建新目录，重复同一章的理解与运行测试。

## 通过与失败

一章通过需要同时满足：

- 无提示指出正确的第一文件与第一动作；
- 关键新术语在使用前有操作性解释；
- 聚焦测试从预期红灯变绿；
- 最高提示不超过 L3，且 L3 只用于正常算法挣扎；
- 学生能解释首次失败属于哪一层；
- 教材、目标测试与 commit diff 没有路径、签名或行为漂移。

以下任一情况使教材失败：

- 学生理解概念却无法确定从哪里写；
- 正文命令或路径与教学历史不一致；
- 必须先看完整 target 才能开始；
- 测试的首次偏差不是正文承诺的失败；
- 陪练必须给 L4 才能弥补正文遗漏。

实验无法模拟人类疲劳、长期记忆与动机，因此通过只证明存在一条可执行的学习
路径，不证明所有读者都能以相同速度完成。
