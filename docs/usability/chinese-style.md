# 教材中文表达契约

目标不是降低技术密度，而是让读者一次读懂。代码标识、协议名和必要的英文术语
可以保留；句子的骨架要用自然中文。

## 一句话怎么过关

每句话都应该回答三个问题：谁做、做什么、结果是什么。主语沿用上一句时可以省略，
但不能让读者猜动作属于模型、工具、循环还是测试。

优先写：

> `push()` 收到终态后，先完成最终 Promise，再把终态交给迭代器。

不要写：

> 终态完成语义经由同一提交点向两个消费视角进行投影。

两句的技术信息相同，前一句更容易执行。

## 保留精度的七条规则

1. 先写具体动作，再给抽象名称。先说“事件先到就放进数组”，再把数组叫
   `queue`。
2. 一句话只承担一条主要因果链。出现三个以上“如果、因此、同时、否则”时，
   拆成两句。
3. 不连续堆名词。把“运行时状态所有权边界”改成“谁保存运行状态，谁负责结束它”。
4. 英文只保留代码里的正式名字。普通动作写中文：用“测试依据”而不是
   `oracle`，用“样例数据”而不是 `fixture`；首次出现时可以写
   “样例数据（fixture）”。
5. `parent`、`target`、`queue`、`waiter` 等课程关键词首次出现时就地解释，
   后面才允许直接使用。
6. 少用固定反转句。每章“不是 A，而是 B”最多两次；能直接下判断就直接说。
7. 读出声检查。若一句话不像工程师会对身边同事说的话，就重写；不要靠括号和
   破折号把四个想法塞进一句。

## 不能靠脚本完成的检查

自动测试只拦截明显套话和重复句式，不能判断一句中文是否平顺。学生与陪练每章
都要额外回答：

- 哪一句第一次读时需要回头？
- 这句话缺主语、动作不清，还是术语出现得太早？
- 保留全部技术信息后，怎样改成你会直接说出口的话？

全书完成后，由一名不参与实现的中文编辑逐章通读。只有自动检查和人工通读都通过，
语言质量才算过关。
