# Глоссарий Pi

Этот файл фиксирует значения ключевых понятий в контексте Pi Textbook. Он не заменяет общетехнический словарь: сюда попадают термины, важные для понимания курса или требующие единого толкования.

## Правила ведения

- Термины располагаются по алфавиту по их основному написанию.
- Для каждого термина указывается рекомендуемое написание в тексте.
- Определение объясняет понятие в контексте Pi, а не во всей индустрии.
- Если перевод спорный, решение сначала обсуждается и фиксируется в `TRANSLATION.md`.
- Не добавлять термин только потому, что он однажды встретился в тексте.

## Agent Loop

**Написание в тексте:** Agent Loop

Основной цикл работы агента. В каждой итерации runtime передаёт модели текущее состояние, получает ответ, при необходимости выполняет вызванные инструменты, обновляет состояние и решает, должна ли начаться следующая итерация.

Agent Loop превращает одиночный запрос к модели в управляемый процесс, способный выполнять последовательность действий.

## checkpoint

**Написание в тексте:** checkpoint

Зафиксированное состояние проекта или учебной реализации, к которому можно вернуться. В курсе каждая глава создаёт новый checkpoint, отражающий очередной архитектурный этап.

Checkpoint нужен не только для сохранения кода, но и для сравнения того, как меняется система после добавления новой возможности.

## context window

**Написание в тексте:** контекстное окно

Объём входного контекста, который модель может обработать за один запрос. В него входят системные инструкции, история сообщений, результаты инструментов и другие данные, переданные модели.

Ограниченность контекстного окна создаёт необходимость управлять историей и применять сжатие контекста.

## context compression

**Написание в тексте:** сжатие контекста

Процесс сокращения накопленной истории с сохранением информации, необходимой для продолжения работы агента. Сжатие позволяет удерживать длительную сессию внутри доступного контекстного окна.

Сжатие контекста не равно механическому удалению старых сообщений: важные решения, факты и текущее состояние должны сохраняться.

## offline model

**Написание в тексте:** офлайн-модель

Модель, запускаемая локально и не требующая обращения к внешнему API для генерации ответа. В начальных главах курса офлайн-модель позволяет разобрать базовую архитектуру агента без сетевых зависимостей.

## prompt

**Написание в тексте:** prompt

Текстовые инструкции и данные, передаваемые модели. В зависимости от контекста prompt может включать системную инструкцию, пользовательский запрос, историю сообщений и результаты работы инструментов.

Термин сохраняется на английском, поскольку в курсе он используется как самостоятельное техническое понятие.

## runtime

**Написание в тексте:** runtime

Исполняющая среда агента, которая управляет его жизненным циклом: состоянием, обращениями к модели, потоковой обработкой, вызовами инструментов, ошибками, сессиями и другими инфраструктурными механизмами.

В контексте Pi runtime — это не просто момент выполнения программы, а слой, связывающий основные подсистемы агента.

## Session Tree

**Написание в тексте:** дерево сессий

Структура, представляющая развитие сессии как ветвящуюся историю, а не только как линейную последовательность сообщений. Ветвление позволяет продолжить работу от предыдущего состояния, не уничтожая альтернативный путь.

## Streaming

**Написание в тексте:** потоковая обработка

Обработка ответа модели по мере поступления отдельных фрагментов, а не только после завершения всей генерации. Она позволяет раньше показывать текст пользователю, обрабатывать события и реагировать на ошибки или вызовы инструментов.

## tool

**Написание в тексте:** инструмент

Внешняя возможность, доступная модели через runtime: функция, команда, API или другое действие с формально описанным входом и результатом.

Модель не выполняет инструмент самостоятельно. Она формирует запрос, который проверяет и исполняет runtime.

## tool call

**Написание в тексте:** вызов инструмента

Структурированный запрос модели на выполнение конкретного инструмента с заданными аргументами. Runtime разбирает запрос, проверяет его и возвращает результат в Agent Loop.

## Tool Calling

**Написание в тексте:** Tool Calling

Механизм, позволяющий модели выбирать и вызывать инструменты через структурированный интерфейс. Он включает описание доступных инструментов, формирование вызова моделью, проверку аргументов, выполнение и возврат результата.

Tool Calling шире отдельного вызова инструмента: это весь механизм взаимодействия модели с внешними действиями.

## trace

**Написание в тексте:** трассировка

Последовательная запись значимых событий выполнения агента: обращений к модели, частей потокового ответа, вызовов инструментов, изменений состояния и ошибок.

Трассировка помогает восстановить ход выполнения и определить слой, на котором возникла проблема.

## working memory

**Написание в тексте:** рабочая память

Текущее оперативное состояние агента, необходимое для выполнения задачи в рамках активной сессии. В неё могут входить история диалога, промежуточные результаты, выбранные действия и данные инструментов.

Рабочую память не следует автоматически отождествлять с долговременной памятью агента.
